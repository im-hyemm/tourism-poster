# 관광데이터 공모전 프로젝트 하네스 구성 계획

## 요약

`AGENTS.md`, 공모전 문맥 스킬, 데이터별 스킬, 노트북 작성 스킬, 시각화 스킬로 구성한다. 데이터 특성은 공모전 문맥과 섞지 않고 각 데이터 소스가 독립적으로 관리한다. 노트북은 별도 생성 스크립트나 검증기를 두지 않고 `.ipynb`로 직접 생성한다.

## 주요 변경

- `AGENTS.md`
  - 한국어 응답, PEP 8, 한국어 Google Style docstring, YAGNI를 상시 규칙으로 지정한다.
  - 프로젝트 목적, 원본 데이터 보호, `src/path.py` 사용, 산출물 저장 위치만 간결하게 명시한다.
  - 공모전 문맥·데이터·노트북·시각화 작업을 각각 해당 스킬로 라우팅한다.
  - 새 참고 문서에 기존 분석 결과를 반영할 때는 두 EDA 노트북만 신뢰 가능한 초기 근거로 사용한다.
  - 다른 노트북은 명시적인 수정·검토 작업에서는 열 수 있지만, 검증 전에는 분석 근거로 인용하지 않는다.

- 공모전 문맥 스킬
  - `use-tourism-context`는 모집요강, 연구 목적, 과거 수상작 패턴만 관리한다.
  - 필수 데이터 조건, 평가 배점, 제출 규격, 가산점과 정책 제언 요구를 요약한다.
  - 수상작 6개의 문제 구성, 근거 제시, 정책 연결, 포스터 전달 방식을 정리하되 데이터 특성이나 현재 분석 결과는 포함하지 않는다.

- 데이터별 스킬
  - `use-national-travel-survey`: 2025년 국민여행조사 SAV, 유저가이드, 설문지, 코드북, 변수 문서, 프로젝트 코드북의 조사 단위·가중치·결측 코드·변수 해석·주의사항을 관리한다.
  - `use-national-travel-survey`:
    `national_travel_survey_region_code.csv`의 키, 행정구역 수준, 코드 형식,
    중복·결합 규칙도 함께 관리한다.
  - `use-population-decline-data`: `pop_decline_danger_region.csv`의 지역 단위, 지정 기준 필드, 값의 의미, 지역코드 결합 규칙을 관리한다.
  - 각 데이터 스킬은 독립된 `SKILL.md`와 필요한 `references/`만 가진다. 데이터 간 결합 규칙은 관련된 두 스킬이 서로를 읽도록 안내하되 동일 내용을 중복 저장하지 않는다.
  - 노트북 결과에서 데이터 특성을 보완할 때는
    `notebooks/02_EDA/260713_연고관광_EDA.ipynb`와
    `notebooks/02_EDA/260713_연고관광_통합_EDA.ipynb`만 사용한다.

- 노트북 스킬
  - `build-analysis-notebook`은 `SKILL.md`와 UI 메타데이터만 두고 `scripts/`, 별도 생성기, 별도 validator를 포함하지 않는다.
  - 새 노트북 요청 시 처음부터 `notebooks/구분/YYMMDD_분석목적.ipynb`를 직접
    생성한다.
  - 유효한 노트북 구조를 위해 작업 시 `nbformat`을 사용하되 프로젝트에 생성 스크립트를 남기지 않는다.
  - 셀은 목적, 환경·경로 설정, 데이터 로드, 품질 확인, 전처리, 분석, 시각화, 요약 순으로 구성한다.
  - 공통 경로와 시각화 모듈을 import하고 절대경로, 숨은 실행 상태, 불필요한 대형 출력은 사용하지 않는다.
  - 결과 실행이 요청 범위에 포함된 경우 생성된 `.ipynb` 자체를 위에서 아래로 실행하며, 별도 검증 파일은 만들지 않는다.

- 시각화 스킬 및 공통 모듈
  - `visualize-tourism-results`에 색상 의미, 글자 크기, 그래프 선택, 저장 규격과 한글 표시 규칙을 둔다.
  - `src/visualization.py`에서 Pretendard Regular·Medium·SemiBold·Bold OTF를 직접 등록하고 `apply_plot_style()`과 공통 팔레트를 제공한다.
  - 기본 크기는 본문 11, 축 제목 13, 그림 제목 16, 범례 10으로 통일한다.
  - 팔레트는 파랑 `#2F5D8C`, 청록 `#2A9D8F`, 주황 `#E76F51`, 금색 `#E9C46A`, 중립 회색 `#6B7280`, 부정 강조 `#C44E52`, 배경 `#FAFAF8`로 고정한다.
  - 폰트 확인 스크립트나 별도 시각화 validator는 추가하지 않는다.

## 확인 기준

- 모든 스킬의 이름과 frontmatter가 유효하고 작업 설명에 따라 서로 구분되어 호출된다.
- `use-tourism-context`에 데이터 스키마·가중치·변수 설명이 섞이지 않는다.
- 각 데이터의 특성과 결합 규칙이 해당 데이터 스킬에서만 관리된다.
- 새 참고 문서에 허용된 두 노트북 외의 분석 결과가 근거로 포함되지 않는다.
- 노트북 스킬에 `scripts/`, validator, 샘플 변환 파일이 생성되지 않는다.
- `src.visualization`을 적용한 그래프에서 프로젝트의 Pretendard가 사용되고 한글 제목·축·범례가 정상 출력된다.
- 기존 노트북, 원본 데이터와 현재 분석 결과는 수정하지 않는다.

## 가정

- 데이터별 관리를 데이터 소스별 독립 스킬로 구현한다.
- 다른 노트북에 대한 제한은 파일 접근 금지가 아니라 분석 근거 사용 제한이다.
- 상세 분석 전략이나 추천 통계기법은 하네스에 포함하지 않는다.
- 개인정보 동의서처럼 하네스 구성에 불필요한 개인 문서는 읽거나 요약하지 않는다.

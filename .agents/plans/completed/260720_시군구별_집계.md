# 국민여행조사 3개년 전체 여행의 지역(시군구) 단위 집계

## Context

기존 지역 후보지 선정 노트북들(`260720_연고관광_지역후보지_선정_2025년/3개년`)은
응답자당 CHECK='Y'로 선택된 **대표 여행 1건**만 지역 단위로 펼쳤다. 이 방식은
대표 여행으로 선택되지 않는 CASE 3(단순 가족·친지·친구 방문)·CASE 5(단순
출장)의 실제 방문 지역 정보를 통째로 누락시킨다(대표 여행의 CASE는 실측
검증 결과 1·2·4만 나온다). 사용자는 이 문제를 인지하고, 이번에는
`national_travel_survey_2023_2025_preprocessed_all_tour.csv`(응답자별
`D_TRA1~6_*` 여행 슬롯을 모두 보존한 파일)로 **모든 여행·모든 방문지**를
지역 단위로 재집계하려 한다.

집계 목적: 시군구별로 (1) 얼마나 많은 여행이 그 지역을 다녀갔는지, (2)
`WT_DOM`으로 확대한 실제 규모는 얼마인지, (3) CASE(여행유형)별로 이게 어떻게
나뉘는지, (4) 그 지역을 대표 여행으로 방문한 사람들의 A계열 응답 프로필은
어떤지를 표로 만든다. 이 결과는 포스터의 "연고 방문을 활용한 지역관광 활성화"
정책 제언에서 지역별 잠재력·특성 근거로 쓰일 예정이다.

세션 중 사용자와 다음 계산 방식을 확정했다:

- 지역은 한 여행이 여러 곳을 방문할 수 있는 **다중응답**이고, CASE는 여행
  1건당 값이 하나뿐인 **배타적 파티션**이다. 따라서 지역별 소계의 합은 전체
  여행 수를 초과할 수 있고(다중응답의 정상적 성질), CASE별 소계의 합은 전체와
  정확히 일치해야 한다.
- "가중 지역 규모" 지표는 하나만 만든다:
  `WT_DOM × (그 지역 체류일 / 그 여행의 체류일 합)`을 지역별로 합산한 값.
  (사용자 예시: A지역 2일, B지역 1일, WT_DOM=12 → A는 12×2/3=8, B는
  12×1/3=4로 배분되어 합이 12로 보존됨.) 가중치만 곱한 별도 열은 만들지
  않는다(의미가 겹침).
- 비중의 분모는 여행에 신고된 전체 여행일수(`D_TRA{k}_S_Day`, 단위가
  "박"이라 +1 필요)가 아니라, **그 여행 안에서 실제 계산된 방문지별 체류일의
  합**을 쓴다. 이렇게 해야 비중의 합이 항상 정확히 1이 되어 지역 합계가 전체
  여행 규모와 어긋나지 않는다. 신고된 전체 일수와의 차이는 별도 QC로만
  검증한다.
- A계열은 응답자당 대표 여행(`D_TRA{k}_CHECK=='Y'`) 1건에만 존재하며, 이
  대표 여행의 CASE는 실측 검증 결과 항상 1·2·4다(케이스 3·5는 0건). 따라서
  A계열 지역 프로필 계산 시 별도 CASE 필터 없이 결측 제거만 하면 자동으로
  CASE 3·5가 빠진다. A계열 값은 그 대표 여행이 방문한 지역 각각에 **체류일
  비중을 나누지 않고 그대로** 배정한다(여행 전체 경험을 나타내는 값이라
  안분 대상이 아님).
- A계열 요약 통계: 이진(0/1) 값은 가중 평균(비중), 다범주 명목형은 가중
  최빈값, 순위형/척도형은 가중 중앙값. 통합 코드북의 `column_type`은
  이진·명목·척도를 구분하지 않고 전부 `nominal`로 표시하므로, 관측값 집합이
  `{0,1}`인지로 이진 여부를 자동 판정하고, 순위형(만족도 `A9`, `A9A_*`,
  `A11`, `A3_RANKW_*`, `D_TRA*_B7_RANKW_*` 등)은 기존
  `260720_연고관광_특성_분석_3개년.py`의 `is_categorical_feature` /
  `derived_categorical_features` 판정 방식을 참고해 별도 목록으로 지정한다.

## 구현 단계

### 1. 로드·품질 확인

- `national_travel_survey_2023_2025_preprocessed_all_tour.csv`,
  `..._all_tour_codebook.csv`, `national_travel_survey_region_code.csv` 로드
  (`src.path.NATIONAL_TRAVEL_SURVEY_PREPROCESSED_DATA_DIR`,
  `NATIONAL_TRAVEL_SURVEY_RAW_DATA_DIR` 사용).
- `YEAR+ID` 유일성, `WT_DOM` 결측·양수 확인(`data-guide.md` 최소 품질 확인
  체크리스트 그대로 적용).
- `region_codes["spot_code"] = 시도_코드*1000 + 시군구_코드`로 5자리 코드
  생성, 229행 유일성 확인(기존 스크립트 패턴 재사용).

### 2. 여행(trip) 단위 long 변환

- `D_TRA{k}_CASE`가 비결측인 슬롯(k=1~6)만 트립으로 인정, 키는
  `YEAR+ID+TRIP_NO(k)`.
- 트립별 `WT_DOM`(응답자 값 그대로, 슬롯마다 반복), `CASE`, `CHECK` 보존.

### 3. 방문지(spot) 단위 long 변환과 체류일 계산

- 각 트립 안에서 `D_TRA{k}_{j}_SPOT`(j=1~17, 존재하는 슬롯만)을 melt.
- 방문지별 `SYEAR/SMONTH/SDAY`~`EYEAR/EMONTH/EDAY`로 `region_days = (종료일 -
시작일).days + 1` 계산(음수·결측은 제외, 날짜 파싱 실패는 QC로 별도 집계).
- 트립 내부에서 `trip_day_sum = sum(region_days)`로 정규화 분모를 만들고,
  신고값(`D_TRA{k}_S_Day` + 1)과 비교해 `validation_summary.csv`에 기록.
- `day_share = region_days / trip_day_sum`(트립 내 지역별 비중, 합=1).

### 4. 지역코드 결합

- `spot_code`를 `region_codes`와 `many_to_one`으로 병합(기존 스크립트의
  `build_visits_long` 패턴 재사용), 미매칭은 임의 보정 없이
  `region_unmatched_spot_codes.csv`로 남긴다.

### 5. 지역별 집계

- 같은 트립이 같은 지역을 여러 방문지 슬롯에 걸쳐 기록했으면 `region_days`는
  합치고, 존재 판정(단순 카운트)은 트립×지역 기준으로 dedup한다.
- 비가중 여행 수: 트립×지역 유일 키 개수.
- 가중 지역 규모: `sum(WT_DOM × day_share)`를 지역별로 합산.
- CASE별로 동일 계산 반복 후, `sum(CASE 소계) == 전체 소계`를 지역마다 assert.
- 전체 검증: `sum(전 지역 가중 지역 규모) `는 다중응답이라 `sum(WT_DOM)`(트립
  유일 기준)보다 크거나 같을 수 있음을 표에 주석으로 남기고, 대신 트립
  하나의 `day_share` 합이 1인지를 검증 지표로 삼는다.

### 6. A계열 지역 프로필

- 응답자별 `D_TRA{k}_CHECK=='Y'`인 k를 찾아 그 트립의 `YEAR+ID+TRIP_NO`를
  대표 여행 키로 확정(구현은 `260720_연고관광_지역후보지_선정_3개년.py`가
  이미 쓰는 CHECK 로직과 동일 원리, 다만 all_tour 슬롯 구조에 맞게 재작성).
- 대표 여행이 방문한 지역들(3단계에서 만든 방문지-지역 매핑)에 A계열 값을
  안분 없이 그대로 배정(다중 지역이면 각 지역에 동일하게 반복 배정).
- A계열 열을 이진/명목/척도로 분류하고 가중 평균·최빈값·중앙값 함수를 각각
  구현(`data-guide.md`의 가중 중앙값 정의: 값 정렬 후 누적 가중치가 목표
  비율에 처음 도달하는 값 사용).
- 지역별로 비가중 N, 가중 분모(`sum(WT_DOM)`), 각 A계열 열의 결측 수를 함께
  기록해 지역 방문 규모 표와 분모가 다르다는 점을 명시한다.

### 7. 시각화(간단)

- 가중 지역 규모 상위 15개 시군구 막대그래프, CASE 구성비 스택 막대 1개
  (`src.visualization.apply_plot_style`, `COLORS` 사용, 기존 스크립트 스타일
  그대로).

### 8. 핵심 결과와 한계 셀

- 다중응답 지역 합계와 배타적 CASE 합계의 차이, A계열 표의 대표여행 한정
  커버리지 한계, 미매칭 지역코드 건수를 명시.

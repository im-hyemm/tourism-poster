# 3개년 연고관광 사전 층화 군집분석 노트북 신설 (2단계 실행)

## Context

기존 `notebooks/03_Modeling/260719_연고관광_사전층화_클러스터링_2025년.ipynb`는 2025년 SAV
원본만 읽고 소수 변수(F2 행동특성 약 30개)로 CASE 2(관광 포함 가족·친지·친구 방문)를
당일/숙박 층으로 나눠 5개 군집 모형(유클리드·Gower·오토인코더 × K-means·K-medoids)을
비교했다. 사용자는 3개년 통합·조화 전처리본
(`data/preprocess/national_travel_survey/national_travel_survey_2023_2025_preprocessed.csv`,
156,050행×592열)으로 같은 방법론을 재현하되 변수를 최대한 확장하고 싶어한다. 다만 변수를
한 번에 크게 늘리면 결과를 바로 비교하기 어려우므로, **먼저 기존 F2 변수에 인구통계만
추가한 축소판을 돌려 저장·시각화하고, 그 다음 소비·활동 세부항목까지 포함한 확장판을
돌려 별도로 저장·시각화**하는 2단계 구조로 만든다. 각 단계 결과는 원본 분석 데이터에
`군집` 열을 추가한 라벨링 데이터로도 저장한다.

사용자 확인 사항:

- 인구통계(BSEX, BAGE, BJOB, BINC1/2, BEDU, BMAR, BFAM, BARA, BMON,
  DQ3A/DQ5AC/DQ7/DQ8)는 **군집 생성 입력에 포함**(만족도처럼 프로파일링 전용이 아님).
- `D1_1~9`/`PD1_*`/`ND_TOTAL`(월 단위 여행용품 구입비, 여행 단위 지출이 아님)은 **제외**.
- 5개 모형·오토인코더 구조는 유지하고 **인코더 크기만 확장**(입력 차원 증가 대응).
- 캐싱은 **저장된 파일이 있으면 로드해서 계산을 건너뛰는 방식**.
- **1단계**: 기존 2025년판 F2(여행 준비·관광활동·동반·체류숙박·이동방문·소비, ~30개 변수)를
  3개년 컬럼명으로 재구성 + 인구통계(F0) 추가 → 실행·저장·시각화.
- **2단계**: 소비·활동 세부항목까지 포함한 전체 확장 변수셋(F0~F4) → 실행·저장·시각화.
- 두 단계 모두 최종 결과를 저장할 때 분석 대상 원본 데이터(`analysis_data`)에 `군집` 열을
  추가한 라벨링 데이터를 별도로 저장한다.

## 3. 두 단계의 feature_domain 정의

- **`FEATURE_DOMAINS_BASELINE`**: 2025년판 F2 6개 영역(여행 준비/관광활동/동반 형태/
  체류·숙박/이동·방문/소비)을 3개년 컬럼명으로 재구성(예: `D_TRA_B7_1`에서
  `car_dependence`/`public_transport` 파생, 코드북 값라벨로 1=자가용·8=렌트→차량,
  2/3/4/5/6/7→대중교통 확인) + **`인구통계` 영역 신설**(`BSEX, BAGE, BJOB, BINC1, BINC2,
BEDU, BMAR, BFAM, BARA, BMON, DQ3A, DQ5AC, DQ7, DQ8`).
- **`FEATURE_DOMAINS_FULL`**: 위 baseline에 아래를 추가/세분화.
    - 소비: `A7_TOTAL/NA7_TOTAL/NA7_1~10`(사전지출), 목적지 지출 카테고리 합계(총액)
      `A8A~A8J, A8` + 1인당 세부 `NA8A_1~3, NA8B, NA8C_1~14, NA8D_1~3, NA8E_1~4, NA8F_1~6,
NA8FA_1~4, NA8G_1~6, NA8H_1~5, NA8I_1~3, NA8J_1, NA8`, 세부 지출 비중 `A8SA~A8SF`,
      `trip_total_cost=D_TRA_COST`, `trip_cost_per_person=D_TRA_ONE_COST`.
    - 준비·정보: `A1A`(예약 시점), `A3_RANKW_1~15`(방문지 선택 이유), `A5A_1~3`/`A5A_RANKW_*`
      (세부 정보원).
    - 그 외 F1/F2 로직은 baseline과 동일.
    - **공통 제외**: `D1_*/PD1_*/D_TOTAL/ND_TOTAL`, 동반인원수 P-접두 열, `D_TRA_NUM`.
    - **외부 프로파일(두 단계 모두 군집 입력 제외)**: `A9, A10, A11, A9A_1~12`(코드 9→NaN),
      `A12_1~6`(여행을 통한 영향, 결과지표로 취급), `YEAR`.
- `categorical_features`는 코드북 `column_type == "nominal"`인 원본 열 + 파생 카테고리
  (`party_group`, `primary_transport` 등)로 자동 구성.

## 4. 재사용 파이프라인 함수(4개로 분리)

Baseline/Full 모두 같은 로직을 타므로 재사용하되, 오래 걸리는 군집 적합과 이후 선정·해석
단계를 각각 별도 함수·별도 셀로 나눠 중간 결과를 노트북에서 바로 확인할 수 있게 한다. 각
함수는 이전 단계 함수가 반환한 딕셔너리를 인자로 받아 다음 단계에 필요한 딕셔너리를
반환한다(단계 사이 중간 산출물은 joblib 캐시가 아니라 노트북 변수로만 유지).

```python
def fit_stratified_clustering(phase_name, feature_domain, categorical_features):
    """한 단계의 전처리와 5모형×K×시드 군집 적합만 수행한다(오래 걸리는 부분)."""

def select_optimal_k(phase_name, fit_context):
    """층·모형별 목적함수 곡선에서 객관적 엘보우 K를 선정한다."""

def select_optimal_model(phase_name, feature_domain, fit_context, k_context):
    """엘보우 K 후보를 자체/공통 Gower 실루엣과 안정성 ARI로 Pareto 선택한다."""

def identify_defining_features(phase_name, feature_domain, categorical_features, fit_context, model_context):
    """최종 군집의 규모·프로파일과 핵심 정의 특성(lift)을 계산·저장한다."""
```

내부 단계(기존 2025년판 로직 재사용 + 캐싱 추가):

1. **`fit_stratified_clustering`** — 층별 상수 변수 제외(`stratum_features`,
   `constant_features` 표, `phase_name` 접두 저장) → `build_euclidean_matrix`/
   `build_gower_matrix`/`autoencoder_embedding`(은닉층 `(64, 16, 64)`로 확장, 입력 차원 증가
   대응) → 5모형×K=1~8×5시드 적합. **캐싱**: `load_or_compute(path, compute_fn)` 헬퍼로
   `MODELS_DIR / phase_name / "preprocessing" / f"{층}_euclidean.joblib"`,
   `..._gower_distance.joblib`, `MODELS_DIR / phase_name / "autoencoder" / f"{층}_seed{seed}.joblib"`,
   `MODELS_DIR / phase_name / model_safe_name / f"{층}_fit_cache.joblib"`(`{(seed, k): (labels, objective)}`)
   경로가 있으면 로드, 없으면 계산 후 저장. `stratum_data`, `stratum_features`,
   `euclidean_inputs`, `gower_distances`, `autoencoder_inputs`, `label_store`, `fit_results`를
   담은 `fit_context` 딕셔너리를 반환한다. 노트북에서 baseline/full 각각 별도 셀로 호출한다
   (가장 오래 걸리는 셀이므로 다른 선정·해석 셀과 분리).
2. **`select_optimal_k`** — `fit_context["fit_results"]`로 목적함수 정규화 →
   층·모형별 스크리 곡선과 엘보우 K 계산·그림 저장(`{phase_name}_stratified_cluster_scree.png`,
   `..._elbow.csv`). `curve_summary`, `elbow_table`을 담은 `k_context`를 반환한다.
3. **`select_optimal_model`** — 엘보우 K 후보마다 자체/공통 Gower 실루엣 재계산(캐싱:
   `MODELS_DIR / phase_name / model_safe_name / f"{층}_final_selection.joblib"`) → Pareto
   선택(최소 군집비중 5%, **안정성 ARI 0.5**) → 실루엣 비교 그림·모형 비교/선택 표 저장
   (`..._silhouette.png`, `..._model_comparison.csv`, `..._selection.csv`). `model_comparison`,
   `selection_table`을 담은 `model_context`를 반환한다.
4. **`identify_defining_features`** — 최종 선택 결과로 `analysis_data`에 `군집` 열 배정 →
   군집 규모·외부 프로파일(`..._final_profile.csv`, `..._external_profile.csv`) → lift 계산
   (`..._lift.csv`) → 핵심 정의 특성 히트맵(`feature_labels`는
   `codebook.set_index("column_name")["column_label"]`에서 조회 + 파생 변수만 보완 dict,
   `..._behavior_lift.png`) 저장.
5. **군집 라벨링 데이터 저장(4단계 내부)**: `analysis_data`(정제 후 원본 스케일)에 `군집`
   열을 추가한 사본을 **`TABLES_DIR / f"{phase_name}_stratified_cluster_labeled_data.csv"`**
   (outputs, `data/preprocess`가 아님)로 저장(`ID, YEAR, 층, 군집` + 나머지 정제된 원본 컬럼
   유지, 스케일링/원-핫 변환 전 값). 2025년판 노트북과 동일한 저장 위치 관례를 따른다.

`MIN_STABILITY_ARI = 0.5`(기존 0.70에서 완화. 3개년 표본·확장 변수셋에서는 더 엄격한 기준이
안정 후보를 과도하게 탈락시킬 수 있어 사용자 지시로 조정).

## 5. 노트북 실행 순서

1~2(공통 로드·정제) → 3(두 feature_domain 정의) → 4의 4개 함수 정의(같은 셀 또는 연속
셀)에 이어, baseline/full 각 단계를 아래처럼 4개 셀로 나눠 순서대로 실행한다.

1. `fit_stratified_clustering("baseline", FEATURE_DOMAINS_BASELINE, CATEGORICAL_FEATURES_BASELINE)`
   (가장 오래 걸리는 셀, 마크다운에 명시)
2. `select_optimal_k("baseline", baseline_fit)`
3. `select_optimal_model("baseline", FEATURE_DOMAINS_BASELINE, baseline_fit, baseline_k)`
4. `identify_defining_features("baseline", FEATURE_DOMAINS_BASELINE, CATEGORICAL_FEATURES_BASELINE, baseline_fit, baseline_model)`

같은 순서로 `full` 단계 4개 셀을 반복한다(변수 수가 많아 1단계보다 오래 걸릴 수 있음을
1번 셀 앞 마크다운에 명시) → 핵심 결과·한계(두 단계 비교: 인구통계 포함 단순 모형 대비 세부
변수 확장 모형의 군집 수·안정성·해석 차이 요약).

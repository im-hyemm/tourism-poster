# 3개년 연고관광 특성 분석 노트북 재작성

## Context

기존 `notebooks/03_Modeling/260719_연고관광_특성_분석_2025년.ipynb`는 2025년 원본
SAV만 읽고 소수의 변수만 손으로 골라 유형1(일반 관광) vs 유형2(관광 포함
가족·친지·친구 방문) 이진분류를 했다. 사용자는 이 접근이 변수를 너무 많이
생략했다고 판단해, `data/preprocess/national_travel_survey/
national_travel_survey_2023_2025_preprocessed.csv`(2023~2025 통합·조화 완료,
156,050행 × 592열)를 사용해 같은 주제를 3개년·훨씬 많은 변수로 재분석하려 한다.
숙박비 등 지출 세부항목(호텔/모텔/펜션 등)까지 포함하고, 코드북의
`column_type`(nominal/scale)을 반영해 데이터를 불러오며, 더미화·정규화·빈 컬럼
검사 등 아직 안 된 전처리를 노트북 안에서 수행한다.

미커밋 상태의 `notebooks/03_Modeling/260720_연고관광_특성_분석_3개년.ipynb`는
원본 SAV를 직접 읽는 2025년판 복제본 초안이라 이번 요구사항과 맞지 않는다.
사용자 확인에 따라 같은 파일명을 전면 재작성하고, 대응하는 생성 스크립트
`script/260720_연고관광_특성_분석_3개년.py`를 새로 만들어 이후에는
`build-analysis-notebook` 스킬의 "생성 스크립트가 있는 노트북" 규칙을 따른다.

사용자 확정 사항:
- 데이터 소스: `national_travel_survey_2023_2025_preprocessed.csv` +
  `national_travel_survey_2023_2025_preprocessed_codebook.csv`(컬럼별
  `column_type`, `integrated_value_labels`, `structural_missing_code` 포함).
- 지출 세부항목(예: A8C_1~14 호텔/모텔/펜션)은 1인당(N-prefix) 금액을 기본으로
  쓰고, 카테고리 합계(A8A~A8J, A7_TOTAL, A8, D_TOTAL 등)는 총액을 유지한다.
  동반인원수(P-prefix)는 사용하지 않는다(이미 `party_size`로 통제).
- 모델은 Dummy, Elastic Net 로지스틱, CatBoost, 랜덤포레스트 4개만 비교하고
  (의사결정나무·Voting·Stacking 제외) SHAP 해석은 CatBoost·랜덤포레스트에
  적용한다.
- 학습된 파이프라인·하이퍼파라미터·예측 결과를
  `outputs/260720_연고관광_특성_분석_3개년/model/{모델명}/`에 저장해, 추후
  재학습 없이 지표 재계산·그래프 재작성이 가능하게 한다.
- 타깃은 기존과 동일하게 "선택된 여행의 CASE가 1(유형1) 또는 2(유형2)"인
  응답자의 이진분류를 유지한다.
- 원-핫 인코딩·스케일링까지 끝난 전처리 완료 특성 행렬을 별도 클러스터링
  분석에서 재사용할 수 있도록 `data/preprocess/`에 저장한다(아래 16단계).

## 데이터 구조 확인 결과 (탐색으로 확인함)

- 분석 단위는 응답자×월 1행이며, 키는 `ID`(이미 `기본ID_일련번호` 형태로 행마다
  고유) + `YEAR`. `D_TRA_CASE`는 그 달에 CHECK=Y로 선택된 대표 여행이 있을 때만
  값이 있고, 없으면 전부 결측이다 → 유형1/2 필터링이 곧 "그 달에 대표 여행 있음"
  필터가 된다.
- 이 CSV는 이미 `D_TRA1_..D_TRA6_` 슬롯 중 CHECK=Y 슬롯을 선택해 `D_TRA_*`(슬롯
  번호 없음)로 평탄화했다. 방문지는 `D_TRA_{1~17}_SPOT`(방문 지역),
  `D_TRA_{1~17}_Q6`(숙박시설, nominal), `D_TRA_{1~17}_Q6_Ar`(숙박 지역코드,
  scale)로 남아 있다. 즉 기존 노트북의 "최근 상세여행 슬롯 선택" 로직은
  더 이상 필요 없다.
- `D_TRA_{1~17}_{SYEAR,SMONTH,SDAY,EYEAR,EMONTH,EDAY}` (총 102열)는 방문지별
  세부 일자다. 사용자 요청대로 제외한다. 여행 전체의
  `D_TRA_SYEAR/SMONTH/SDAY/EYEAR/EMONTH/EDAY`(슬롯 번호 없는 6열)는 계절·요일
  파생에 계속 사용한다.
- 전체 592열 중 37열은 항상 결측(`D_TRA_15~17_*` 등 관측되지 않은 방문지
  슬롯 위주)이다. 데이터 품질 단계에서 자동으로 찾아 제거한다.
- `structural_missing_code`가 채워진 열은 15개(`D_TRA_B7_1~3`,
  `D_TRA_B7_RANKW_1~12`)뿐이며 `"-1=해당 없음..."` 형태다. 정규식으로 코드값을
  추출해 결측 처리한다. 그 외에 알려진 구조적 결측은 만족도 세부항목
  `A9A_1`~`A9A_12` 각각의 **응답 척도값 9**("경험 해보지 못함",
  `integrated_value_labels`로 확인됨. 예: `A9A_9`=9번째 항목인 "지역
  관광종사자의 친절성"과는 별개로, `A9A_9` 열 안에서도 응답값 9는 여전히
  "경험 해보지 못함"을 뜻한다)이며, 기존 2025년 노트북과 동일하게
  `A9A_1~A9A_12` 전 항목에 대해 값 9를 NaN으로 바꾸는 수동 규칙을 적용한다.
- `ZQ1_*`(비여행 이유)처럼 유형1/2 모집단에서는 구조적으로 전부 결측인 열이
  있을 수 있다. 전역 빈 컬럼 검사와 별개로, CASE 1/2로 표본을 제한한 뒤
  같은 빈 컬럼 검사를 한 번 더 돌려 이런 열도 함께 제거한다.
- `D1_1~9`/`D_TOTAL`/`ND_TOTAL`, `DQ3A/DQ5AC/DQ7/DQ8`, `BMON` 등은 기존
  노트북에 없던 열로, 각각 "그 달 국내 구매 여행용품 지출", 가구·건강 관련
  인구통계다. 최대한 많은 변수 사용 방침에 따라 F0/F4 그룹에 포함한다.
- 지출 세부항목은 총액/인원수(P)/1인당(N) 삼각 구조다
  (`A8C_1`, `PA8C_1`, `NA8C_1` 등). 사용자 결정에 따라 세부항목은 `N` 위주,
  카테고리 합계(`A8A`~`A8J`, `A7_TOTAL`, `A8`, `D_TOTAL`)는 총액을 쓴다.

## 구현 계획

### 1. 생성 스크립트 신설

`script/260720_연고관광_특성_분석_3개년.py`를 `script/260719_연고관광_특성_분석_2025년.py`
패턴 그대로 새로 작성한다(모듈 독스트링에 대상 노트북 경로와 내용 요약,
`markdown()`/`code()` 헬퍼, `nbformat.write`로 직접 기록). 완성 후 실행해
기존 미커밋 `.ipynb`를 덮어써 생성한다.

### 2. 목적/환경 셀

- 목적 markdown: 3개년 통합, 확장된 변수셋, 통합 전처리 CSV 사용, 모델 4종 +
  SHAP, 산출물 저장 방식을 명시.
- import는 기존 2025년판에서 `DecisionTreeClassifier`, `VotingClassifier`,
  `StackingClassifier` 제거, `joblib`, `json` 추가.
- 경로는 `src.path.NATIONAL_TRAVEL_SURVEY_PREPROCESSED_DATA_DIR`,
  `NATIONAL_TRAVEL_SURVEY_RAW_DATA_DIR`(지역코드 csv용),
  `create_output_directories("260720_연고관광_특성_분석_3개년.ipynb")` 사용.
  모델 저장용 `MODELS_DIR = OUTPUTS_DIR / "260720_연고관광_특성_분석_3개년" / "model"`을
  직접 만들고 모델별 하위 폴더는 저장 시점에 `mkdir(parents=True, exist_ok=True)`.
  (`src/path.py`의 `create_output_directories`는 다른 노트북들이 2-튜플
  언패킹으로 쓰고 있어 반환 형태를 바꾸지 않는다.)
- `RANDOM_STATE`, `TEST_SIZE`, `N_SPLITS`, `N_REPEATS`, `SHAP_SAMPLE_PER_FOLD`는
  기존값 유지.

### 3. 데이터 로드 (column_type 반영)

- `codebook = pd.read_csv(..._preprocessed_codebook.csv, encoding="utf-8-sig")`로
  `column_name → column_type/structural_missing_code/integrated_value_labels`
  매핑을 만든다.
- `raw_data = pd.read_csv(..._preprocessed.csv, low_memory=False)`.
- `column_type == "scale"`인 열은 `pd.to_numeric`으로 강제, `"nominal"`인 열은
  값이 전부 정수형으로 해석 가능하면 `Int64`(nullable)로, 아니면(`Y`/빈 문자열
  같은 코드) 문자열로 유지하는 헬퍼 함수 `cast_by_column_type()`을 작성한다.
  (raw CSV는 이미 결측 섞인 정수 코드가 float로 저장돼 있어 코드값 보존을 위해
  필요하다.)
- 불러온 shape, `column_type` 분포, 결측 비율 상위 표를 출력.

### 4. 데이터 품질과 분석 단위 확인

- `ID` 결측 없음/유일성, `WT_DOM` 결측·양수 확인(기존 로직 재사용).
- 전역 빈 컬럼(37개 예상) 자동 탐지·제거, 목록을 표로 저장
  (`TABLES_DIR / "affinity3y_dropped_empty_columns.csv"`).
- 사용자 지정 제외: `D_TRA_{1~17}_{SYEAR,SMONTH,SDAY,EYEAR,EMONTH,EDAY}`
  (정규식으로 매칭해 제거, 방문지 순서/전체 일정은 별도 변수로 대체된다는 점을
  markdown에 명시).
- `D_TRA_CASE`를 숫자로 캐스팅 후 `isin([1, 2])`로 분석 대상 필터링
  (`selected_case`/`target` 생성은 기존과 동일하되 슬롯 선택 로직은 삭제).
- 표본 흐름표(`sample_flow`, 기존과 동일 형식)에 연도별 N도 추가한다(3개년
  재분석의 핵심 검증 포인트).
- 필터링된 표본에서 다시 한 번 전부-결측 컬럼 검사를 돌려(예: `ZQ1_*`) 추가
  제거하고 별도 표로 기록한다.

### 5. 전처리·특성공학 (코드북 기반, 그룹은 F0~F5 유지)

기존 F0~F5 명칭과 CV 비교 구조는 유지하되, 하드코딩된 소수 리스트 대신
코드북 접두어 매칭으로 그룹을 채운다.

- 구조적 결측 처리: `structural_missing_code`의 `"-1=..."` 패턴 파싱 → 해당
  값 NaN 치환(15개 `D_TRA_B7*` 열). `A9A_*`의 코드 9 → NaN(기존 규칙 유지).
- **F0 여행자 특성**: `BSEX, BAGE, BJOB, BINC1, BINC2, BEDU, BMAR, BFAM, BARA,
  BMON, DQ3A, DQ5AC, DQ7, DQ8`, `YEAR`(연도 고정효과), `monthly_total_trip_count`
  (`SA1_1~5` 합, 원열은 F0에서 제외해 기존과 동일한 누출 방지 유지).
- **F1 여행 구조·동반**: 기존 로직 그대로(월/계절/평일·주말·공휴일 포함 여부,
  `nights`, `trip_days`, `overnight_trip`, `trip_vac`) +
  `D_TRA_B7_1~3`(교통수단, 통합본에는 슬롯 구분 없이 이미 top-level로 존재) +
  `D_TRA_B7_RANKW_1~12`, `party_size(A6)`, `child_count/with_child(A6A)`,
  `with_pet(A6C)`, `A6B_1~7`(동반유형, 통합본에서 이미 0/1로 변환돼 있으므로
  그대로 사용).
- **F2 여행지역**: 기존 지역코드 병합 로직(시도 더미, 거주지 일치, 수도권
  패턴, 행정구역 패턴, 미매칭 카운트) 재사용하되 슬롯 선택 없이
  `D_TRA_{1~17}_SPOT`을 바로 melt한다. 추가로 `D_TRA_{1~17}_Q6`(숙박시설
  분포를 유형별 개수/여부로 요약) 포함.
- **F3 여행 준비·활동**: `A2_1~11`(사전예약, 통합본에서 이미 0/1),
  `A3_*`/`A3_RANKW_*`(방문지 선택 이유), `A4_1~21`(활동, 이미 0/1),
  `A5_1~3`/`A5A_1~3`(정보경로 및 세부 웹사이트, 이미 재매핑됨), `A12_1~6`을
  코드북 라벨로 의미 확인 후 포함.
- **F4 소비·평가**: 카테고리 합계
  (`A7_TOTAL, NA7_TOTAL, A8A~A8J, A8, NA8, D_TOTAL, ND_TOTAL`) +
  세부항목 1인당(N-prefix: `NA7_1~10, NA8A_1~3, NA8B, NA8C_1~14, NA8D_1~3,
  NA8E_1~4, NA8F_1~6, NA8FA_1~4, NA8G_1~6, NA8H_1~5, NA8I_1~3, NA8J_1,
  ND1_1~9`) + 기존 `total_spend/spend_per_person/spend_per_person_day` +
  카테고리 비중(`share_a8x`) + 만족도(`A9, A9A_1~12, A10, A11`).
- **F5 연고신호(민감도 전용)**: 기존과 동일(`family_visit_activity`,
  `family_home_lodging`).
- `categorical_features`는 더 이상 수동 집합이 아니라 코드북의
  `column_type == "nominal"`을 그대로 사용(파생 변수는 값 종류로 자동 판정:
  object/범주형이면 categorical).

### 6. Feature set 확정과 누출 자동 검사

- `feature_sets = {"F0": ..., "F0+F1": ..., ..., "F0+F1+F2+F3+F4": ...,
  "전체+F5(민감도)": ...}` 동일 패턴.
- `forbidden_patterns`에 `D_TRA_CASE`, `D_TRA_CHECK`, `SA1_` 원열,
  `D_TRA_{1~17}_{SYEAR..EDAY}`(이미 제외됐지만 방어적으로 재확인) 포함.
- 최종 feature 수, 원-핫 인코딩 후 예상 차원(카테고리 수 합)을 표로 출력해
  차원 폭발 여부를 점검.

### 7. 모집단 EDA

- 기존 가중 평균/구성비 로직 재사용 + 연도별(2023/2024/2025) 유형1·2 가중
  구성비를 추가로 비교(3개년 재분석의 핵심 부가가치).

### 8. 파이프라인 (전처리 fold-safe 유지 + 정규화 방법 결정)

- `build_preprocessor()`를 3-branch `ColumnTransformer`로 확장:
  - 금전형 수치(`NA*, PA*, A7*, A8*, D1_*, D_TOTAL, ND_TOTAL` 패턴):
    `SimpleImputer(median) → FunctionTransformer(np.log1p) → StandardScaler()`.
    지출액은 오른쪽으로 크게 치우친 분포라 `MinMaxScaler`는 이상치에 압축되고,
    `log1p + StandardScaler`가 Elastic Net의 계수 해석과 정규화 페널티에
    더 적합하다는 점을 markdown에 근거로 명시.
  - 그 외 수치형: 기존과 동일(`SimpleImputer(median) → StandardScaler()`).
  - 범주형: 기존과 동일(`SimpleImputer(most_frequent) → OneHotEncoder(drop="first",
    handle_unknown="ignore")`).
- `cross_validate_probabilities()` 등 헬퍼는 기존 그대로 재사용.

### 9. F0~F5 단계별 기여도

- Elastic Net으로 기존과 동일하게 반복.

### 10. 알고리즘 비교 (축소된 4개 모델)

- `model_definitions = {"Dummy": ..., "Elastic Net 로지스틱": ...,
  "랜덤 포레스트": ..., "CatBoost": ...}` (의사결정나무·Voting·Stacking 제거).
- 교차검증 후 각 모델을 전체 훈련 데이터로 최종 fit하고, 다음을
  `MODELS_DIR / model_name /`에 저장하는 `persist_model()` 헬퍼를 추가:
  - `pipeline.joblib` (joblib.dump, fold-safe 파이프라인 전체)
  - `params.json` (`get_params()` 중 직렬화 가능한 값 또는 생성자 인자)
  - `cv_metrics.csv` (fold별 f1/precision/recall/pr_auc)
  - `oof_probabilities.csv` (훈련 인덱스, OOF 확률, 정답)
  - `test_predictions.csv` (테스트 인덱스, 확률, 예측, 정답) — 11단계 최종
    평가 이후 채워짐.
- 알고리즘 비교 막대그래프는 기존과 동일한 스타일로 4개 모델만 표시.

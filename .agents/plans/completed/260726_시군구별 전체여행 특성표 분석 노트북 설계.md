# 시군구별 전체여행 특성표 분석 노트북 설계

## 1. 목표·산출물·참조 자료의 역할

### 목표

2023~2025년 국민여행조사 통합 전처리본에서 다시 계산하여 229개 시군구별 wide 특성표를 만든다.

- 기존 표의 전체여행 규모·CASE별 가중 규모·CASE 2 군집 구성은 그대로 재현한다.
- 동료 표의 비용·기간·숙박·예약·활동·만족도·재방문·정책점수 의도를 반영한다.
- 공통 여행문항은 CASE 1~5 모든 여행, A시리즈는 대표여행 CASE 1·2·4로 엄격히 분리한다.
- 사용자가 제외하기로 한 CASE 1–CASE 2 비용 격차 지표는 만들지 않는다.

## 2. 최종 테이블 열 그룹과 분석대상

### A. 키·전체여행 규모·CASE 구성

분석대상은 CASE 1~5의 모든 여행 슬롯과 모든 유효 방문지다.

- `spot_code`, `시도명`, `시군구명`
- 기존 이름을 유지하는 열:
  - `비가중_여행수`
  - `가중_지역규모`
  - `전국_대비_비중(%)`
  - `CASE1_관광휴양`부터 `CASE5_출장업무_관광미포함`
- CASE별 비가중 여행-지역 건수:
  - `case{1..5}_trip_n_all_trip_case15`
- CASE별 지역 내 가중 구성비:
  - `case{1..5}_share_weighted_all_trip_case15_pct`
- 동료 표의 연고방문 파생지표를 올바른 전체여행 기준으로 재계산:
  - `hometown_visit_n_all_trip_case23`
  - `hometown_visit_weighted_all_trip_case23`
  - `hometown_visit_share_w_all_trip_case15_pct`
  - `rank_by_hometown_visit_weighted_all_trip_case23`
  - `rank_by_hometown_visit_share_all_trip_case23`

CASE별 비가중 값은 여행-시군구 유일 건수이고, 기존 `CASE*` 열은 여행 건수가 아니라 `WT_DOM × day_share`의 합임을 코드북에 명시한다.

### B. CASE 2 연고관광 군집 구성

기존 노트북과 동일하게 대표여행 CASE 2이면서 군집 라벨이 있는 여행만 대상으로 한다.

- 기존 군집별 가중 규모 5열
- `연고관광_가중규모_합`
- 기존 군집별 구성비 5열

군집 구성비 분모는 CASE 2 군집 라벨 결합 표본의 해당 시군구 가중 규모다. CASE 2+3 연고방문 규모와 혼용하지 않는다.

### C. CASE 1~5 공통 여행특성

모든 여행 슬롯의 D_TRA 공통문항을 사용하고, 가중치는 모두 `WT_DOM × day_share`다.

- `total_cost_mean_w_all_trip_case15`
- `total_cost_median_w_all_trip_case15`
- `one_person_cost_mean_w_all_trip_case15`
- `one_person_cost_median_w_all_trip_case15`
- `travel_nights_mean_w_all_trip_case15`
- `overnight_rate_w_all_trip_case15_pct`
- `family_friend_lodging_rate_w_all_trip_case15_pct`

동료 표의 비가중 평균·비가중 중앙값은 노트북 QC에서만 산출하고 최종 feature에는 넣지 않는다. CASE 1–CASE 2 비용 평균 및 비용 격차도 제외한다.

### D. CASE 1·2·4 대표여행 A시리즈 특성

`D_TRA{k}_CHECK == 'Y'`인 대표여행을 찾고 CASE 1·2·4만 포함한다.

- 모집단 표시:
  - `rep_trip_n_case124`
  - `rep_trip_weighted_denom_case124`
- 동일한 대표여행 모집단에서 계산:
  - `family_friend_lodging_rate_w_rep_trip_case124_pct`
  - `no_reservation_rate_w_rep_trip_case124_pct`
  - `nature_activity_rate_w_rep_trip_case124_pct`
  - `food_activity_rate_w_rep_trip_case124_pct`
  - `rest_activity_rate_w_rep_trip_case124_pct`
  - `family_visit_activity_rate_w_rep_trip_case124_pct`
  - `satisfaction_mean_w_rep_trip_case124`
  - `revisit_intent_mean_w_rep_trip_case124`
- 동료 파생값:
  - `activity_potential_rep_trip_case124_pct`
  - `low_spending_conversion_hint_rep_trip_case124`
  - `is_reliable_rep_trip_case124`

`is_reliable_rep_trip_case124`는 동료 기준을 존중해 비가중 N이 10 이상이면 참으로 두되, 이를 이용해 행이나 지표를 제거하지 않는다.

기존 노트북의 대표여행 배정 방식은 유지한다. 대표여행 특성은 여행 전체에 대한 응답이므로 방문한 각 시군구에 한 번씩 배정하고 `day_share`로 나누지 않는다. 같은 여행에서 같은 시군구가 여러 방문지 슬롯에 나타나면 먼저 중복 제거한다. 이 방식은 임의의 지역별 A 응답을 만들지 않으면서 기존 표 및 동료 표와 정의를 맞춘다.

## 3. 계산식·가중치·결측 규칙

여행 \(t\), 시군구 \(r\), 가중치 \(w_t=WT\_DOM\), 방문지 체류일 \(d_{tr}\)로 정의한다.

\[
day\_share_{tr}=\frac{d_{tr}}{\sum_r d_{tr}},\qquad
g_{tr}=w_t\times day\_share_{tr}
\]

- 같은 여행·시군구의 여러 방문지 슬롯은 체류일을 합산한 후 한 행으로 만든다.
- `day_share` 분모는 기존 노트북처럼 해당 여행에서 계산 가능한 방문지별 체류일 합이다.
- 날짜 파싱 실패, 0일 이하 체류일, 지역코드 미매칭 방문지는 지역 집계에서 제외하고 QC에 남긴다.

### 규모·CASE

- 비가중 여행 수: \(\sum_t I(t가 r 방문)\)
- 가중 지역 규모: \(\sum_t g_{tr}\)
- CASE \(c\) 가중 규모: \(\sum_t g_{tr}I(CASE_t=c)\)
- CASE 구성비: `CASE c 가중 규모 / 전체 가중 지역 규모 × 100`
- 연고방문 규모: `CASE 2 가중 규모 + CASE 3 가중 규모`
- 연고방문 비중: `연고방문 가중 규모 / 전체 가중 지역 규모 × 100`

### 공통 연속형 지표

변수 \(y_t\)에 대해:

- 가중 평균: \(\sum g_{tr}y_t/\sum g_{tr}\)
- 가중 중앙값: \(y_t\)로 정렬한 뒤 누적 \(g_{tr}\)가 유효 가중치의 50%에 처음 도달한 값
- 결측은 변수별 분자·분모에서 함께 제외하고 0으로 대체하지 않는다.

현재 사전 점검에서는 CASE 1~5 총 84,673건 모두 `S_Day`, `COST`, `NUM`, `ONE_COST`가 관측됐다. 따라서 최종 CSV에서는 `비가중_여행수`와 `가중_지역규모`가 공통 지표의 표본수·가중 분모 역할을 한다. 실행 시 응답률 100%가 깨지면 조용히 다른 분모로 계산하지 않고 검증을 중단한다.

- 여행기간은 `D_TRA{k}_S_Day`의 숙박일수 그대로 사용한다.
- 숙박여행 여부는 `S_Day >= 1`.
- 가족·친지집 숙박은 해당 여행-시군구의 방문지 슬롯 중 `Q6 == 12`가 하나라도 있으면 1이다.
- 당일여행 또는 해당 시군구에 숙박시설 기록이 없는 경우는 지역 내 가족·친지집 숙박 0으로 정의한다.
- 알 수 없는 Q6 코드나 전체 숙박여행에서 Q6가 전혀 없는 경우는 별도 QC 대상으로 둔다.

### 대표여행 A시리즈

대표여행-시군구 자료의 가중치는 \(w_t\)이며 `day_share`를 곱하지 않는다.

- A 이진 비율: \(\sum w_tI(A=1)/\sum w_t\), 결측 제외
- 만족도·재방문 의향: \(\sum w_ty_t/\sum w_t\)
- `activity_potential`: 자연·음식·휴식 활동 비율의 단순 산술평균
- 정책점수:

\[
0.35\times 가족친지집숙박률+
0.25\times 무예약률+
0.25\times 활동잠재력+
0.15\times \left(\frac{재방문의향평균}{5}\times100\right)
\]

정책점수의 네 구성요소를 모두 대표여행 CASE 1·2·4, 동일한 시군구 배정, 동일한 `WT_DOM` 분모로 계산한다.

CASE 3·5 행에 A값이 남아 있어도 사용하지 않는다. 현재 점검 결과 대표여행은 72,133건이며 CASE 1 57,904건, CASE 2 12,790건, CASE 4 1,439건이고, 선정 A문항은 각 CASE에서 100% 관측됐다.

## 5. 품질검증·기존 표 비교·보고서 표기

### 필수 검증

- `YEAR+ID` 유일성, `WT_DOM` 결측 없음·양수
- 여행 키 `YEAR+ID+TRIP_NO` 유일성
- CASE가 1~5이고 현재 CASE별 건수가 59,514 / 13,107 / 8,638 / 1,518 / 1,896인지 확인
- 응답자별 CHECK='Y'가 최대 1건인지 확인
- 대표여행 CASE가 1·2·4만 존재하고 CASE 3·5가 A자료에 배정되지 않았는지 확인
- 지역코드 229개 및 `spot_code` 유일성, 병합 `many_to_one`, 미매칭 코드 목록
- 여행-시군구 중복 방문 슬롯 수와 dedup 전후 행 수
- 각 포함 여행의 `day_share` 합이 1인지 확인
- 전체 `가중_지역규모` 합이 유효 지역이 있는 여행의 `WT_DOM` 합과 일치하는지 확인
- 지역별 CASE 가중 규모 합이 `가중_지역규모`와 일치하는지 확인
- 지역별 CASE 건수 합이 `비가중_여행수`와 일치하는지 확인
- CASE 구성비 합이 분모가 있는 시군구에서 100%인지 확인
- 군집 구성비 합이 해당 시군구에서 1인지 확인
- A문항별 가중 분모가 대표여행 가중 분모를 넘지 않는지 확인
- 비율 0~100, 만족·재방문 1~5, 비용·기간 음수 없음, 정책점수 0~100
- 최종 229행, `spot_code`와 시도·시군구 키 중복 없음, 무한대 없음
- 코드북 행 수·열 순서가 최종 CSV와 정확히 일치

### 기존 표와 반드시 일치할 열

동일 입력과 군집 파일을 사용할 때 다음 값은 기존 `region_trip_feature.csv`와 일치해야 한다.

- 시도명·시군구명
- `비가중_여행수`, `가중_지역규모`, `전국_대비_비중(%)`
- CASE 1~5 가중 규모
- 기존 군집별 가중 규모 5열
- `연고관광_가중규모_합`
- 기존 군집별 구성비 5열

정수·키는 완전일치, 가중 실수는 `atol=1e-6` 수준으로 비교한다.

기존 A프로필의 `비가중_N`, `가중_분모`는 새 `rep_trip_n_case124`, `rep_trip_weighted_denom_case124`와 일치해야 한다. 기존 `A2_11_비중`, `A4_1/2/6/18_비중`은 새 백분율을 100으로 나눈 값과 일치해야 한다.

### 차이가 나도 되는 열

- 기존 A 만족도·재방문 열은 가중 중앙값이지만 새 표는 동료 의도를 따라 가중 평균이므로 달라도 된다.
- 동료 표의 모든 CASE 2 전용 행동특성은 새 CASE 1·2·4 대표여행 값과 달라야 정상이다.
- 공통 비용·기간·숙박 특성은 동료의 대표여행 CASE 2가 아니라 모든 여행 CASE 1~5와 `day_share`를 사용하므로 달라진다.
- 정책점수는 동료 CASE 2 점수가 아니라 대표여행 CASE 1·2·4 점수이므로 달라진다.
- 기존 표의 나머지 전체 A시리즈 200여 열은 최종 wide 표에 그대로 승계하지 않고, 동료 표가 의도한 핵심 A변수로 대체한다.
- `spot_code`, CASE별 비가중 건수·비중, CASE 2+3 파생값은 신규 열이다.
- 인구감소지역 여부·행정구역 메모는 여행특성 산출 범위가 아니므로 포함하지 않는다.
- CASE 1–CASE 2 비용 평균과 비용 격차는 사용자 결정에 따라 제외한다.

### 포스터·보고서 표기

- 공통 특성: **“전체여행 특성: 2023~2025년 CASE 1~5 모든 여행, WT_DOM×시군구 체류일 비중”**
- A 특성: **“대표여행 응답 특성: CHECK=Y, CASE 1·2·4, WT_DOM; 대표여행 방문 시군구별 중복 배정”**
- 군집: **“대표 연고관광 여행(CASE 2) 군집 구성, WT_DOM×체류일 비중”**
- 정책점수: **“대표여행 CASE 1·2·4 기반 탐색적 전환 힌트”**

“시군구 전체여행 만족도”처럼 A시리즈를 전체여행 지표로 오인시키는 표현은 사용하지 않는다. 표·그림에는 비가중 N과 가중 분모를 함께 표기하고, 다중응답 활동률은 합이 100%일 필요가 없음을 주석으로 남긴다. 정책점수는 모집단 비율이나 인과효과가 아니라 탐색적 합성지표로만 해석한다.

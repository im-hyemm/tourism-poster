# 분석 노트북 작성

## 새 노트북

1. `notebooks/구분/YYMMDD_분석목적.ipynb` 이름을 사용한다.
2. 프로젝트 루트의 `script/`에 노트북과 같은 파일명의 생성 스크립트를 만든다.
   예: `notebooks/01_Preprocess/YYMMDD_분석목적.ipynb`의 생성 스크립트는
   `script/YYMMDD_분석목적.py`로 둔다.
3. 생성 스크립트 상단의 모듈 독스트링에 담당 노트북의 프로젝트 상대 경로와
   노트북에 담기는 내용을 작성한다.
4. `nbformat.v4.new_notebook`, `new_markdown_cell`, `new_code_cell`로 노트북
   객체와 셀을 만들고 `nbformat.write`로 대상 `.ipynb`에 직접 기록한다.
   생성 스크립트는 `script/`에 계속 보관해 이후 수정과 노트북 동기화에
   재사용한다.
5. 노트북 외에 템플릿이나 validator를 만들지 않는다.
6. 커널은 프로젝트 Python 3 환경의 tourism 가상환경을 사용한다.
7. 다음 순서로 셀을 구성한다.
    - 분석 목적과 범위
    - 환경, 공통 경로, 재현성 설정
    - 데이터 로드
    - 데이터 품질과 분석 단위 확인
    - 전처리
    - 분석
    - 시각화
    - 핵심 결과와 한계
    - (마지막 코드 셀) `src.notebook_sync.sync_script_from_notebook` 호출
8. 마지막 코드 셀은 예외 없이 다음을 실행해 이 노트북과 생성 스크립트를
   동기화한다. `notebook_path`는 이 노트북의 프로젝트 루트 기준 상대 경로
   문자열을 그대로 적는다.

    ```python
    from src.notebook_sync import sync_script_from_notebook

    sync_script_from_notebook("notebooks/구분/YYMMDD_분석목적.ipynb")
    ```

    Jupyter에서 노트북을 직접 편집한 뒤 이 셀을 실행하면(저장된 파일 기준으로
    동작하므로 먼저 저장 필요) 생성 스크립트의 `cells` 블록이 노트북의 현재
    상태로 갱신된다. 이 유틸은 `src/notebook_sync.py`에 이미 있으므로 새로
    만들지 않는다.

## 코드 규칙

- 프로젝트 루트를 찾은 뒤 `src.path`의 경로 상수와 함수를 사용한다.
- 저장이 필요한 최종 산출물은 노트북 파일명을
  `create_output_directories()`에 전달하여 `outputs/{노트북 파일명}_{yymmdd_hhmm}/figures/`와
  `outputs/{노트북 파일명}_{yymmdd_hhmm}/tables/`에 저장한다. 파일명에서 `.ipynb` 확장자는
  출력 디렉터리 이름에 포함하지 않는다.
- model을 학습하는 실행 시간이 오래 걸리는 분석은 학습 결과를 반드시 outputs/{노트북 파일명}\_{yymmdd_hhmm}/models/에 저장하여 추후 재현할 수 있도록 한다.
- 저장 경로는 기본적으로 `outputs/`를 쓴다. `data/preprocess/`에 저장하는
  코드는 사용자가 명시적으로 요청하거나 직접 추가·수정한 경우에만 넣는다.
- 시각화 전에 `src.visualization.apply_plot_style()`을 호출한다.
- 필요한 데이터 스킬을 먼저 읽고 키, 가중치, 분기 규칙을 적용한다.
- 한 코드 셀에는 하나의 분명한 작업만 둔다.
- 파라미터, 필터, 분석 단위, 난수 시드와 입력 파일을 상단에 노출한다.
- 재현성을 위해 일회적으로 실시되는 코드더라도 삭제하지 않고 실행 순서와 결과를 기록한다.
- 큰 표, 디버그 로그, 전체 원자료 출력을 제한한다.
- display, print 사용 시 어떤 목적을 위해 출력하는지 명시한다.
- 반복 사용되는 범용 로직만 `src/` 모듈로 이동한다.

## 노트북 수정

- 이 규칙 도입 전에 만들어진 노트북에는 생성 스크립트를 소급해 만들지 않는다.
  (이 노트북 스킬의 나머지 규칙도 이 규칙 도입 이후 새로 만드는 노트북에만
  적용하며, 기존 노트북에 소급 적용하지 않는다.)
- 대응하는 생성 스크립트가 없는 기존 노트북은 의도와 셀 순서를 보존하고 필요한
  부분만 직접 수정한다.
- 대응하는 생성 스크립트가 있는 노트북은 기본적으로 생성 스크립트를 수정한 뒤
  실행하여 노트북을 다시 생성한다.
- 사용자가 `.ipynb`를 Jupyter에서 직접 수정해 생성 스크립트와 어긋난 경우,
  먼저 `src.notebook_sync.sync_script_from_notebook(notebook_path)`로 생성
  스크립트를 노트북 기준으로 맞춘 뒤 이어서 작업한다(노트북을 다시 원래
  스크립트로 덮어써 직접 수정한 내용을 잃지 않는다).
- 생성 스크립트와 `.ipynb`의 셀 내용, 메타데이터, 실행 전 상태를 일치시킨다.
- 사용자가 특정 노트북을 지정하지 않은 채 기존 결과를 참고하라고 하면
  프로젝트 `AGENTS.md`의 신뢰 노트북 제한을 적용한다.
- 실행 결과가 없는 계산을 요약이나 결론에 적지 않는다.

## 실행

노트북을 생성·수정한 뒤 기본적으로 직접 실행하지 않는다. 코드를 먼저
제공하고, 실행은 사용자가 tourism 가상환경에서 직접 한다. 다음 경우에만
예외로 직접 실행한다.

- 사용자가 실행까지 명시적으로 요청한 경우.
- 실행 시간이 짧아(수 초~수십 초) 결과를 바로 확인하는 편이 더 빠른 경우.

오래 걸리는 분석(대용량 데이터 처리, 모델링, 클러스터링, 대규모 공간 결합 등)은
사용자가 요청하지 않는 한 실행하지 않는다. 직접 실행하는 경우 생성·수정한
`.ipynb`를 위에서 아래로 실행하고, 성공 상태는 노트북 자체의 출력으로
남기며 별도 validator, 검증 스크립트, 검증 결과 파일을 만들지 않는다.
실행할 수 없으면 원인과 필요한 실행 명령을 정확히 알린다.
